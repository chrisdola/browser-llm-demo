On-device inference

Browser LLM demo

The same chat runs three ways on this device. The page does not send the conversation to a server.

  1. 1 Pick a runtime

    Runtime

    Model. Pick a model in step 2. Every option is q4f16 and already compiled for WebLLM. GPU memory is about 380 MB for SmolLM2 360M, 880 MB for Llama 3.2 1B, 1.6 GB for Qwen2.5 1.5B, 1.8 GB for SmolLM2 1.7B, 2.3 GB for Llama 3.2 3B, and 2.5 GB for Qwen2.5 3B.

    In the browser. A web worker owns the engine, so generation stays off the UI thread. Load downloads the weights into the browser cache, then inference runs only on WebGPU. Replies stream through an OpenAI-style chat API and stop at 128 tokens.

    Model. Pick a weight in step 2. The menu lists Qwen2.5 0.5B (q4, about 750 MB), Qwen2.5 1.5B (q4f16, about 1.2 GB), and SmolLM2 1.7B (q4, about 1.4 GB). This demo only generates text.

    In the browser. A second web worker runs the ONNX pipeline. It uses WebGPU when an adapter exists, and WASM on the CPU otherwise. The first Load fetches the weights from Hugging Face into the cache. Tokens stream from the tokenizer, capped at 128 new tokens.

    Model. Gemini Nano, installed and updated by the browser. This page does not choose the weights or the quantization.

    In the browser. It runs on the main thread through LanguageModel, on desktop Chrome 148+ or Edge. Load checks availability and may download Chrome’s model. Replies come from promptStreaming(). The web API does not expose sampling controls, so the shared system prompt asks for a short answer.
